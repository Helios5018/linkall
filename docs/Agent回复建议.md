# LinkAgent 回复建议

2026-10-04 用户授权：在输入法内，基于当前输入框及当前应用的近期记录生成三个候选；后续明确改为 **V → 轻点左 Command**，不使用 V → Enter。第一版为只读检索与一次 LLM 调用，不包含自动发送、工具执行或长期记忆。

## 如何确定“正在回复什么”

记录中的 `app`、`window` 都是采集归属线索，并不证明整个屏幕的文字都来自该应用，也不证明同一窗口始终是同一个聊天。

- 当前输入框为最强意图线索：读取显式选区或 ≤2000 UTF-16 单位的小输入框；空输入框也允许推荐。大选区不截半段后自动覆盖全文；未知目标只复制。
- 当前应用必须精确匹配。当前窗口标题可确认时，历史首先限定同名窗口；不使用其他窗口的记录。没有窗口身份时不猜前一个聊天，退回当前草稿。
- 截图实际是显示器画面。上传资料不使用扁平 `original` OCR 全文：新记录从已验证未被遮挡的前台窗口矩形内选取文字块；旧记录没有矩形证明时，只采用该窗口已有的可见 AX 文字。没有任一证明的截图不进入模型。
- 最近 5 分钟内的同窗口屏幕作为场景锚点，不称为实时截图。截图完全相同时持续延长 `ended`，所以新旧判断用最后观察时间，不能用第一次截图时间。
- 输入原文、语音原始转写、AI 产物和交付文字分别保留。打字记录可能是不完整片段，交付不代表已发送，AI 产物不代表用户确认。

## 如何选取有限资料

查询先在 SQLite 按精确应用和时间过滤；各记录类型分别取最多 24 条，避免高频输入挤掉屏幕/语音。最多回看 30 分钟，不做整库上传。

本地筛选按以下次序执行：

1. 只保留同窗口场景，允许最多 90 秒内同应用、尚未关联窗口的输入片段，并明确标注窗口未确认。
2. 最新屏幕优先；输入草稿和场景文字通过中文双字片段、英文标识词及基于当前候选集的词频权重做相关性排序。它只是轻量词法检索，不声称完成语义记忆。
3. 较早屏幕必须与当前草稿/场景有足够共同信息；10 分钟以前的输入需与草稿强相关。无草稿且无新鲜屏幕时，不用旧片段猜当前任务。
4. 对完全重复内容去重；较早屏幕只补充最新屏幕未出现的行。最新画面优先，旧时间、旧数字只作为较早证据。
5. 最多选 10 条，文字总预算 12000 字；最新屏幕最多 6000 字，其他原文每条最多 1600 字；AI 结果和交付内容使用更小预算。长内容保留场景开头、草稿相关行及末尾，并标注节选。

资料包含记录 ID、最后观察时间、类型、窗口、关联依据、原文、AI 产物、交付内容和节选标记。不会上传图片、音频或整库记录。

## 如何让模型给出建议

复用用户已有的文本 API 配置与 Keychain 凭据，LinkAgent 通过注入的网络函数调用，不依赖 Rime 或持有密钥。一次调用要求模型先判断当前事项与信息缺口，再输出：

- `summary`：简短的当前事项说明；证据不足就明确不足。
- 三个 `candidates`：每项有不同的 `intent`、完整回复 `text`、实际引用的 `evidence_ids`。

草稿优先保留用户意图和语言，空框则找最新明确问题。三条是不同的合理应对方式，不是三个同义句；不为制造差异而替用户改变立场。未确认的日期、金额、接受邀请或完成状态不得编造。OCR、窗口标题、历史文字和草稿均视为不可信资料，不作为工具/系统指令。

本地严格验证恰好三条、非空、不重复、长度上限，以及引用只能来自本次资料。引用校验只能证明 ID 存在，不能证明模型语义一定正确；“查看参考依据”显示当前候选的来源片段和局限，供用户判断。没有有效三条就显示错误，不自动重试或用空泛硬编码回复冒充结果。

## 输入与生命周期

V 为临时预编辑；轻点左 Command（按下到松开 ≤0.6 秒）消费触发字符。连续输入回到原输入引擎；右 Command 沿用语音入口；Command 组合键和长按不触发。

普通输入框的候选支持 1/2/3、↑↓ 后 Enter/Tab、鼠标选择、单条复制和 Esc。普通输入框请求中 Enter/Tab 也被吞掉。普通继续输入取消建议。选中候选是完整替换所捕获草稿/选区，不自动发送；模型换行压成空格，不合成 Return。

普通输入框的目标 PID、编辑器、原文与光标位置要保持一致；切换应用、点击其他位置、普通输入、锁屏、休眠或更改设置取消请求。迟到结果不得落到新的会话。未知结果不重试。记录暂停时只用当前输入框；应用排除在读取与请求之前执行。云端授权关闭时不调用 API。

cmux / Claude Code 等终端不再因无法读取整行而一律仅复制：若能绑定并重新确认同一个终端编辑区域，选择候选通过 IMK 正常文字提交插入当前光标处，保留已有文字，不合成 Return、不使用剪贴板、不替换整行。面板注明“插入光标处，保留已有内容”。终端仅用鼠标点击采用，普通按键取消候选并保持终端原行为，不用数字或 Enter/Tab 选候选：部分终端会把这些键同时交给 PTY，不能声称 IMK 返回已处理就能可靠拦截。终端输出不能用来回读确认输入行，因此记录为已请求上屏，不自动重试。无法确认终端编辑区域时仍仅复制，现有应用排除设置不变。

终端当前草稿仍未直接读取，模型收到 `fieldStatus=unavailable`，与已读取的空输入框区分；不允许把未读取说成“输入框为空”。因此当前终端推荐主要使用筛选后的记录，并不保证理解正在输入的完整草稿。

## 已知局限

- 需要选用 LinkInput；macOS 安全输入/密码框不提供此能力。
- 通用记录尚未保存稳定聊天 ID、浏览器 tab ID 或发言人，因此同名窗口仍可能切过聊天；模型需结合内容甄别，无法证明时建议澄清。当前不接飞书/浏览器专门连接器。
- 没有窗口区域证明的旧 OCR 会被舍弃，可能减少旧记录利用率；这是资料归属不明，不是记录丢失。
- 当前字段和窗口快照并非原子读取；已有按键/焦点校验和晚到丢弃只能降低并发变化风险。未覆盖宿主不保证直接写入。
- 模型建议需由用户选择，不能把通过结构验证等同事实正确。网络延迟、模型拒答或结构错误都可能使本次没有候选。
